# Remedy Mesh — INPUT corpus

Generated by `../generate_input_data.py` (seed=42, reproducible). This folder is
**input only**: raw records the multi-agent system reasons over. **No verdicts are
baked in.** The agents must *derive* the scope-expansion decision and *produce* the
work-products. All company / VIN / supplier names are fictional; the hero case
(CASE-001) is *shaped* on the real, cited NHTSA pattern (24V-104 + 26V422 "fix-the-fix").

## Inputs the agents consume

| File | Rows | Role |
|---|---|---|
| `cases.json` | 30 | Intake queue. `status` is **"New signal"** only — the agent moves it; it is not a pre-set verdict. |
| `complaints.json` | ~500 | Raw geocoded complaints **with VIN, dates, repair record, free-text narrative**. No `post_remedy` flag — the agent derives pre/post from `repair_date` vs `date`. |
| `production_lots.json` | 30 | lot → VIN range → plant/date. `confirmed_by`/`confirmed_ts` are **null** — the Resolution Loop must *obtain* them. |
| `remedy_campaigns.json` | 7 | The original recalls (compliance board data): original VIN/date scope, remedy date, baseline rate. Scope drift is measured **against** these. |
| `policy_rules.json` | 1 | The **referee**: evidence-sufficiency criteria + thresholds. Case-agnostic — thresholds, not answers. |
| `suppliers.json` | 4 | OEM (private target + cost ceiling) + 3 suppliers, each with private capacity/cost and `visible_to` scoped to itself. |
| `dealers.json` | 50 | Service-center contact chain for the Resolution Loop (who did the repair, regional QA contact). |

## Outputs the agents PRODUCE (ship empty)

`activity_log.json`, `negotiation_log.json`, `commitment_ledger.json` — **`[]` at start.**
The agents write these at runtime. Finished-state golden copies live in
`../expected_outputs/` to validate against.

## Key properties (verified by `../validate_layer1.py`)

- **CASE-001 confirms from inputs alone**, firing on **both** triggers:
  post-remedy failure-rate ratio **≈3.76** (≥2.5× the pre-remedy baseline) **and** a
  geographic cluster — then blocks on `install_date_confirmed` until the Resolution
  Loop obtains LOT-4471. LOT-4471's production date (2024-03-12) and VIN range
  (>VXM200000) both fall **outside** CAMP-24V104's original scope → genuine scope drift.
- **Not special-cased:** CASE-015 and CASE-020 also confirm independently.
- **Refuses to guess:** sparse cases resolve to "insufficient evidence / no-signal."
- **Reasons, not pattern-matches:** CASE-009 has a strong post-remedy spike *and* a
  cluster, but its lot is *within* original scope → correctly **not** a scope case
  (flagged as a remedy-quality issue instead).
